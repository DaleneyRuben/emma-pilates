# Product backlog

This is the implementation tracking source of truth. The execution strategy and
definition of done live in [`README.md`](./README.md).

## Status and priority

- `done` — completed and validated; Evidence contains a commit.
- `in progress` — the single item currently being implemented.
- `next` — first item to pull after the current checkpoint.
- `ready` — sufficiently defined and waiting on its dependencies.
- `blocked` — cannot proceed until the named dependency or approval is resolved.
- `later` — intentionally ordered behind higher-priority work.
- `deferred` — outside the initial release.

Priorities describe product value, not strict technical order:

- `P0` — required for the mobile-first release.
- `P1` — backend/reliability work or mobile completeness needed before production.
- `P2` — admin-web delivery, the lowest-priority application surface.
- `P3` — explicitly deferred work.
