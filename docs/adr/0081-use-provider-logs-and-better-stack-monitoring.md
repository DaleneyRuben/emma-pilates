# Use provider logs and Better Stack monitoring

Status: accepted

The NestJS API and worker write structured JSON through Pino to standard output. Northflank remains the initial searchable store for those backend logs and its built-in infrastructure metrics. Every entry carries environment, service, release, severity, and a request, command, or job correlation identifier where applicable. Domain and application code do not depend on Northflank or Better Stack types, and no full distributed-tracing system is introduced initially; correlation identifiers connect the small number of processes until measured debugging needs justify traces.

Better Stack Free is the initial external monitoring and error-reporting service for the NestJS backend, Expo mobile app, and React admin web. It receives sanitized exceptions with environment and release identifiers, non-public source maps uploaded by authorized build workflows, external API and admin-web checks, and worker or scheduled-job heartbeats. Actionable failures generate deduplicated email alerts outside the application and worker being monitored. Northflank continues to provide infrastructure and container signals rather than duplicating all telemetry in another platform.

Telemetry never includes passwords, session credentials, authentication links, authorization headers, request or response bodies, signed object URLs, receipt contents, complete job payloads, or unnecessary personal data. Browser and mobile session replay, automatic interaction capture, and console capture are disabled. Expected RFC 9457 client errors are not reported as application failures. Provider initialization stays at application shells so a free-tier or product change can replace Better Stack without changing domain behavior.

At selection time, the [Better Stack free plan](https://betterstack.com/pricing) combines error tracking, monitors, heartbeats, short-retention telemetry, and email alerts, and its documented application types include NestJS and React Native. Sentry plus UptimeRobot was rejected initially because it would split errors and availability across two services. Logs alone were rejected because mobile and browser failures and silent worker stalls would remain hard to detect. Sending every log and trace to a full observability platform was rejected because Northflank already stores backend logs and metrics and the initial workload does not justify the extra data or complexity.
