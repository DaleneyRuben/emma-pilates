# Host the public pages on Cloudflare Pages

Status: accepted

Both app stores need public web pages before a listing can be submitted: a privacy policy, a support contact, and, for Google Play, a web link where a person can ask for their Account to be deleted without installing the app. The studio publishes them in Spanish as plain static HTML under `apps/public-site/`, with no build step, no JavaScript, no cookies, no analytics, and no third-party requests (fonts fall back to system faces rather than loading Google Fonts), so the privacy page itself collects nothing. The pages follow the design system's palette and type scale by hand; they are legal text, not product screens, so they have no design prompt.

They are served by Cloudflare Pages on the free plan, in the Cloudflare account that already holds the domain's DNS, Email Routing, and R2. The Pages project `emma-pilates-public` is connected to the GitHub repository with `main` as its production branch, no build command, and `apps/public-site` as its output directory, so a merge to `main` publishes the pages the same way it releases the rest of the system. Preview deployments for other branches are turned off. The project answers only on the apex `emmapilatesstudio.com`; no `www` host is added, since every link the stores and apps publish uses the apex. The pages live at `/privacidad`, `/soporte`, and `/eliminar-cuenta`.

Attaching the custom domain adds only a flattened `CNAME` at the apex. The apex's MX and single SPF record for Email Routing, its `cf2024-1._domainkey` DKIM key, and Resend's `send.`, `resend._domainkey`, and `_dmarc` records ([ADR-0094](./0094-use-resend-for-transactional-email.md)) are not touched. The mobile-link hosts `links.emmapilatesstudio.com` and `links-staging.emmapilatesstudio.com` (LNK-001) belong to the API, not to this project, which never claims them; `www` is left unused.

An Account-deletion request from the web is an email to `soporte@emmapilatesstudio.com` from the address of the Account, answered by an operator who closes it from the admin web with the same rules as in-app closure ([BE-007](../implementation/BE-007-data-governance-proposal.md), G2–G7). No web form or endpoint is built: a request volume of a few a year does not justify a public, unauthenticated endpoint that could be abused to close someone else's Account.

Cloudflare Pages was chosen because it is free with no card, needs no new account, serves custom domains with managed certificates, and changes nothing in the DNS zone beyond the apex hostname. GitHub Pages was rejected because it needs GitHub Pro or a public repository for a private repository, which the owner declined. Vercel was rejected because the free Hobby plan already carries the admin web under non-commercial terms, and a second project there adds nothing Cloudflare does not. Cloudflare Workers static assets would also work, but Pages keeps the deployment a directory with no configuration file. Serving the pages from the NestJS API was rejected because policy pages must stay up when the API is paused or failing, and the API's host is not on the domain. A hosted policy generator was rejected because its text would not match what the apps actually collect.
