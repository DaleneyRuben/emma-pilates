# Use Resend for transactional email

Status: accepted

This replaces the provider chosen in [ADR-0031](./0031-use-sendpulse-for-transactional-email.md); every other rule in it stands. Transactional authentication email is sent through Resend's managed service instead of SendPulse. The backend still depends only on the project-owned `AuthenticationEmailDelivery` interface; Resend's API key, request shape, and error codes stay inside one infrastructure adapter, so a later provider again replaces only that adapter.

The rules ADR-0031 set are unchanged. Account or token state and its encrypted pg-boss job commit in one transaction and the API answers only after that commit. The worker rechecks the link before every attempt. Each provider attempt has a hard ten-second deadline. A job gets at most four attempts with pg-boss's bounded backoff inside about ten minutes. Network failures, timeouts, rate limits, and provider server errors retry; invalid requests, rejected recipients, and authentication or configuration errors fail at once. Public flows stay neutral. A hard bounce or complaint suppresses further authentication email to that normalized address, a soft failure does not, and delivery events are applied idempotently after their signature is verified. `provider-accepted` now means Resend accepted the request.

Resend was chosen on 2026-10-19 because SendPulse's free SMTP profile sat in manual moderation from 2026-10-16, with an extra questionnaire answered and still no decision three days later, which blocked launch. Resend has no manual review: the sending domain is verified by DNS and the account can send at once. Its free plan needs no card and includes the HTTP API, SMTP, one verified domain, delivery webhooks, and its own suppression list for hard bounces and complaints. ADR-0031 had already named Resend the preferred developer-experience alternative and rejected it only for its smaller free allowance.

The free plan allows 3,000 emails a month and 100 a day. The studio's expected volume, a handful of registrations, invitations, and recoveries a day, fits comfortably. The risk is a launch-day burst: if more than 100 people register or are invited in one day, Resend answers further sends with a quota error. The adapter treats that as a rate limit, so the job retries for about ten minutes and then fails with that category; the link stays valid and the person can ask for it again the next day, or staff resend it. Before announcing the app widely, the owner either spreads invitations over several days or moves to Resend's paid plan for that month. Free-tier terms remain an external constraint and are checked again before each launch milestone.

The sending domain is `emmapilatesstudio.com`, in Resend's São Paulo region, the closest to Bolivia. Resend's SPF and bounce records live on its `send.` return-path subdomain and its DKIM key on `resend._domainkey`, so the root's single SPF record and Cloudflare Email Routing's MX records stay untouched. DMARC starts at `p=none` with aggregate reports to `soporte@`, and is tightened once the reports are clean. Messages come from `Emma Pilates Studio <no-responder@emmapilatesstudio.com>` and replies go to `soporte@emmapilatesstudio.com`. Open and click tracking stay off, because rewritten links would break authentication links and hurt deliverability.

Resend's delivery webhooks are signed with Svix's scheme (an HMAC over the event id, timestamp, and raw body). The API verifies that signature against a secret kept in the environment provider ([ADR-0079](./0079-keep-runtime-secrets-in-environment-providers.md)), rejects stale timestamps, and records an `email.bounced` event of the permanent type or an `email.complained` event as a suppression keyed by the address digest and the provider event id, so a repeated delivery changes nothing. Resend's own suppression list also refuses addresses that bounced or complained, which protects the domain's reputation even before the application learns of the event.

SendPulse's account holds no data and is no longer used; deleting it is the owner's decision.
